"hephaestus": minor

Each practice now has one review program, its **practice script**. Each review records one result for each practice, with each problem as its own observation. A practice without a script runs the built-in review, as before. A script can prepare what the review checks, decide parts of the practice in code, or ask models where code cannot decide. Earlier releases called a practice's optional script **Static analysis** in the app and **precompute script** in the docs.

- **Results and problems.** A not met result lists its problems, each with its own severity and places. An example is **Not met · 3 problems**. A result can also show one place in the work where the practice is done well. It can also show the questions that the review could not settle. Open questions are never sent as feedback. A met result is never sent to the work as praise. The review on a pull request or merge request speaks only about results that are not met. With no such result, the review posts nothing on the work. **Not applicable** is now **Does not apply**, and **Undetermined** is now **Could not determine**. The severity **Informational** is now **Trivial**: a real but small gap. Pages that said **observation** for the verdict of a practice now say **result**. The browser extension shows **Your results**, and under a not met result the one line of each problem.
- **Problems.** **Practices → Practice reviews** has a new list, **Problems**, between **Results** and **Feedback**. It lists each problem that the reviews recorded, newest first, with its severity, its practice and its place in the work. It filters by severity and origin, and applies the scope of every tab. A row opens the sheet of its result.
- **One check for every result.** The server checks each result in the same way, whatever produced it. It checks each quote against the captured work, and the scope and shape of the result. If one problem or citation fails a check, Hephaestus withholds the whole result of that practice. A withheld not met result never becomes met. The other practices of the review continue.
- **Write.** The practice editor has its own **Script** section, after **When this practice is reviewed**. It links to **AI models** and to the guide [Write a practice script](https://docs.hephaestus.build/admin/practice-scripts). The guide has a tutorial, examples, a local test command, and a brief for an AI assistant. **Technical settings** keeps the identifier and feedback delivery. It no longer opens by itself when the practice has a script.
- **One script form.** Every practice script uses `definePracticeScript`, and its `run` returns the practice's result. `ctx.review()` asks the review to decide with the places, facts and limits that the script prepared. A script that fails gives its practice no result in that review. So does a script that requires a model that the review does not have. The failure is never a statement about the work. A script never falls back to the built-in review.
- **Bundled practices.** The scripts of the bundled practices now prepare the review's input in code and call no models. At its first start, Hephaestus updates each copy of a bundled script that nobody changed. A changed copy stays as it is. Its practice stops with an error until an admin accepts the practice's update or rewrites the script.
- **Connect.** The **API** select of the connection form offers three more APIs for practice scripts. They are the **Decisions API**, the **Embeddings API** and the **Rerank API (Cohere-compatible)**. The API cannot change after you create the connection. When such an endpoint lists no models, you add the model by its ID. Each connection shows an icon for each kind of model that its API serves.
- **Assign.** **AI models** has a second section, **Models for practice scripts**. It has a **Decision model**, an **Embedding model** and a **Reranking model**. Each row shows one column for each tier, and a badge only when it needs a decision. An open row lists the practices that use the model, with unmet needs first. Links such as **Assign a decision model** open the right row.
- **Data handling.** Calls from practice scripts follow the reviewed developer's AI choice. A model for practice scripts is at least as strict as the review's own model. If a review runs on an In-house model, its scripts use only In-house models. A Cloud model for practice scripts that no Cloud review can use shows a note.
- **Know the cause.** A script knows why its practice is in the review: its moment, a recheck, or a request by hand. It also reads the kind and record of the work, the role of the practice, and its criteria. It also reads the practice's previous result on the same work. On a pull request, it gets the lines that changed since that result. The review sees which places are new since then. When a practice runs stays with its moments and review conditions. A script only reads them. [The context](https://docs.hephaestus.build/admin/practice-scripts#the-context) tells more.
- **See each program.** A review has a section **Practice scripts** with one row for each practice. It shows how the practice's program reached its result, or why it stopped. It also shows the program's models with their tier, its calls and its run time. It also shows why calls were not rated, and the first line of an error.
- **Every practice.** On a review's sheet, each practice that ran a program has one line that tells how it ran. The line has at most one link that fixes the cause.
- **See the review's models.** **Technical** on a review's sheet shows the model with its tier and counts **Review model calls**. Its **Cost** also includes what the models of the review's practice scripts cost. **Practice setup** shows an alert when some members do not get a required model. It lists the script's needs beside its code.
- **See the cost.** **AI usage** and each workspace's details on the instance page have a section **Models for practice scripts, by practice**. It splits the cost of each decision, embedding and reranking usage row between practices. Cost that no practice can carry shows as **Not attributed**. Chat calls from a script stay in the review's own cost. So do the review sessions that a script asks for.
- **Usage tables.** Money columns are grouped by purse, **Shared models** and **Own provider**. For each purse, **By run type** shows **Spend** and **Avg per run**. **Models for practice scripts, by practice** shows **Spend** and **Avg per review**. **By day** shows the spend of each purse.
- **Averages and unpriced usage.** An average column shows the same decimals in each cell, such as `$0.004` below one cent. **No price set** appears only when a row has unpriced usage. It counts runs, or reviews in the table by practice, not usage rows. **Runs** counts review attempts and Heph turns only.
- **Budget and cap.** The instance table of workspaces shows the spend of each purse, the shared-model budget, and the provider cap. **Own provider** shows when the month has usage on the workspace's own provider. In the current month, it also shows when the workspace has an enabled model on its own enabled connection. Thus, you can set a provider cap before the first call.
- **Tiles and buttons.** The tiles show the budget or cap, such as `of $25`. They also show **Paused**, **Near the budget**, **Near the cap** or **No price set**. The workspace's cap button names the cap that it changes: **Set provider cap** or **Change provider cap**.
- **Sorting.** The table by practice sorts by each column except **Models**. The instance table of workspaces sorts, filters by name, and shows 25 workspaces on each page.
- **Limits.** Direct model calls from practice scripts count against the same shared-model budget and provider cap as review calls. Cached prompt tokens cost the cache rate, as in review calls. Each review attempt has a limit of 200,000 tokens for the direct model calls of its practice scripts. To change it, set `PRACTICE_REVIEW_DIRECT_MODEL_TOKENS_PER_ATTEMPT`. Reranking providers such as Cohere bill search units instead of tokens. Usage rows keep these search units. Each review attempt has a limit of 1,000 search units for direct calls. To change it, set `PRACTICE_REVIEW_DIRECT_MODEL_SEARCH_UNITS_PER_ATTEMPT`. The review sessions that a script asks for use the review's own work budget. When a limit, the budget or the cap is spent, the proxy refuses further direct calls with HTTP 402. Calls already in flight can still finish, so an attempt can end slightly above a limit.
- **Unreported usage.** A direct call whose provider reports no usage, or whose answer fails after the provider accepted it, counts as a call with unknown usage. Its usage row stays without a price, also after you set a price later.
- **No metered API cost.** A model with **No metered API cost** always records a confirmed $0, also without reported tokens. A priced reranking model that bills search units records its calls without a price. A model price has rates for tokens only.
- **Time.** Each practice's program runs inside the review's own timeout. No time is set aside for scripts before the review. A practice-review timeout below 61 seconds now runs at 61 seconds. The practices of a review run one after the other. Thus, a slow script leaves less time for the practices after it. A custom script runs in its own process, with no credential.
- **Monitor.** `agent.review.practice_scripts` counts how each practice's program ended, by `status`: `ok`, `skipped`, `failed`, `not_reached` or `not_finished`. `llm.proxy.practice_script.unattributed` counts the direct model calls that named no practice, which the proxy refused. It stays at 0 when the agent image matches the server's release. `llm.proxy.budget.blocked` has a new `cap` tag. It names what refused the call: `instance`, `byo` or `practice_script_attempt`.

**Operators:** This release changes the database, the API and the agent image together. Old and new versions cannot run side by side. Before you upgrade, drain the worker roles so that active practice reviews finish. Then stop every runtime role, and make a verified database backup. Upgrade the server, worker and webhook roles, the agent image and the webapp together. Ask your users to update the browser extension.

To go back, restore the backup with the previous release. Ask workspace admins to rewrite each practice script that they changed. A script in the earlier form stops with an error, and there is no grace period. Custom API clients must use the renamed result routes and fields, and send `practiceScript` instead of `precomputeScript`. The migration guide lists every change.
