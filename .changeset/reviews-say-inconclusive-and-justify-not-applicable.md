A review that reads the evidence and genuinely cannot call it now says "Inconclusive" rather than the more obscure wording it used before, and a review that says a practice does not apply to a change now has to say what makes it not apply — naming what the practice looks for and the fact about that change which rules it out. "Not applicable" was previously the only answer that cost nothing to give, so it was collecting cases that were really "we could not tell", which read back as "there was nothing to see here" in a developer's record. Expect fewer not-applicable results and more inconclusive ones; the totals stay the same, but each is now saying what it means.

Every practice that ships with Hephaestus has been swept to match. Where a practice used to answer "does not apply" because something was not there to read — a description field that never synced, a linked issue or design document this review could not open, a commit list it was handed empty — it now answers "inconclusive" and names what it could not read. Where the work genuinely gives it no subject — no error path to judge, no reviewer comment to weigh, no decision to record — it still answers "does not apply", and now states the fact about the change that rules it out. Eleven practices used to settle a real doubt by quietly picking a side: reading an ambiguous sentence as a restatement, an ambiguous symbol as internal, an ambiguous file as hand-written. They now say they could not tell, instead of recording against you a judgement nobody actually made.
