## How to do it

- Go through each item that the issue states.
- For each finished item, tick its box or clearly confirm it in the body or a comment.
- For each item that is not done, name it in a comment and say if it was dropped or deferred. For example, instead of closing with “Done”, write “Export and import are done. Bulk delete is deferred to a new issue.”
- If the issue is already closed and its record is incomplete, add the comment now. The record that a reader sees today is the one that counts.

## When it does not apply

- The issue is still open.
- The issue was closed as not planned, as a duplicate, or because other work replaced it. Its close reason or a comment about this close says so.
- The issue states no outcome that someone can check, such as a topic name with no clear finish.

It still applies when the issue has no checklist and only its title says what must be true when the work is done.

## Common mistakes

- Letting the closed state speak for the issue. Closing it, or merging the pull request or merge request that closes it, does not say which items were done. Instead, tick the items or confirm them in a comment.
- Leaving unfinished items unticked with no word about them. A reader cannot tell if they were done, dropped, or forgotten. Instead, name each one and say what became of it.
- Writing a confirmation, such as “Search is done”, that covers only part of the list. Instead, make clear which finished work the confirmation covers.
- Ticking an item that you did not finish, so that the list looks complete. Instead, leave it open and say that it was deferred.
