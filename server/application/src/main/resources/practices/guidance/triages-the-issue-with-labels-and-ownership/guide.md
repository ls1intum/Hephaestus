## How to do it

- Find the project’s written policy for classifying issues. It often lives in a contributing guide or a triage page.
- For your kind of issue, set each label kind that the policy requires, such as type, priority or size.
- If the policy requires an issue type, set the built-in type or the type label that the policy accepts.
- If the policy requires an owner or a milestone for your kind of issue, set it.
- If the policy requires a team label for the issue, add it. For example, instead of only asking “Can the network team look at this?”, add the required network label.

## When it does not apply

- The project’s written policy says that this kind of issue needs no labels, type, owner or milestone.

A missing policy does not tell you whether classification requirements apply.

## Common mistakes

- Filling in every field you can see. The practice does not ask for that. Instead, set only what the policy asks for on this kind of issue. Fields that it does not ask for can stay empty.
- Copying the labels that other issues carry. A label that many issues use is not a rule. Instead, check what the written policy asks for.
- Picking a kind that does not match the issue, such as labelling a support question as a bug. Instead, pick the kind that the policy defines for this work. If you are not sure, ask a maintainer.

## Sources

- [Issue triage](https://handbook.gitlab.com/handbook/product-development/how-we-work/issue-triage/), GitLab Handbook. GitLab’s written policy asks for type and group labels, plus a severity label for bugs.
- [Issue triage guidelines](https://www.kubernetes.dev/docs/guide/issue-triage/), Kubernetes contributor guide. Kubernetes uses kind, priority and owning-group labels, and an issue with no priority label has not been prioritized.
- [Best practices for Projects](https://docs.github.com/en/issues/planning-and-tracking-with-projects/learning-about-projects/best-practices-for-projects), GitHub Docs. GitHub suggests issue types to classify work and assignees to show who is responsible.
