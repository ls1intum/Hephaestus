## How to do it

- Before you file a big issue, list the parts that someone could ship or pick up on their own.
- Give each part its own check box, or open it as a child issue. For example, instead of one line that asks for “export, settings and alerts”, write three check boxes. Name them “Add the export”, “Add the settings page” and “Send the alerts”.
- Name the work to do in each item, so that anyone can tell when it’s done.
- If the issue is an epic or a tracking issue, give its work a task list or child issues.
- If you find the parts later, add a task list or child-issue links to the issue body or a comment.

## When it does not apply

- The issue asks a question, asks for support or opens a discussion, and asks for no concrete work.
- The issue body is empty, has only a title or is an unchanged template.
- The issue asks for one focused piece of work, such as one feature or one bug fix.

It still applies when one short sentence asks for several separate things, such as a rename, a new tab and a new default.

## Common mistakes

- Judging size by the length of the issue. Instead, look at the parts. Two or more parts that could ship or go to different people are large work, even in one line.
- Writing the parts as one paragraph. Instead, give each part its own check box or child issue, so each one can reach done on its own.
- Labeling an issue as an epic with nothing under it. Instead, add the task list or link the child issues when you open it.
- Treating a list of checks as the plan. A list of things to verify does not say what to build. Instead, add the steps of the work, such as “add the endpoint”.

## Sources

- [Adding sub-issues](https://docs.github.com/en/issues/tracking-your-work-with-issues/using-issues/adding-sub-issues), GitHub Docs. Sub-issues break larger work into tasks, and the parent issue shows their progress.
- [Tasks](https://docs.gitlab.com/user/tasks/), GitLab Docs. Tasks break an issue into smaller items that you can track and assign, and the issue shows their progress.
- [INVEST in good stories, and SMART tasks](https://xp123.com/invest-in-good-stories-and-smart-tasks/), Bill Wake, 2003. A good task makes clear what work it involves and what the team means by done.
